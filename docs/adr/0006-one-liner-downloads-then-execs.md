# 一行流只做下载与 exec，引导在拿到终端后发生

需求要求既能仓库内 `./install.sh` 安装，也能 `curl -fsSL <url> | sh` 一行安装。后者有个
固有限制：`sh` 从管道读脚本，stdin 被脚本本身占用，任何交互式提问都会立刻读到 EOF。

pi 的官方安装器用的是同一模式——`curl ... | sh` 里的 `sh` 只是引导器，它把真正的安装器
落盘再 exec，于是真安装器拥有干净的真终端。

因此决定：一行流脚本只做「下载仓库 + exec 真正的安装器」，不做任何提问。

## Consequences

- 引导（探测、逐条提问、多选）只存在于真正的安装器里，且只在它有真终端时发生；没有终端
  时按探测结果全自动，不提问。
- `npx qodbuddy2pi install` 与 GitHub Release 的启动脚本走同一条路径：都是下载／定位仓库
  再 exec 同一个安装器，不重写安装逻辑。
- 安装器需要征询意见的地方（例如写 PATH）都必须能在无终端时安全跳过，而不是挂住。
