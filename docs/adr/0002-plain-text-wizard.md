# 接入走纯文本引导，TUI 只做运维

最初的设计把接入也做进 TUI：`assets/wizard.js` 是一个全屏菜单，列出四个接入目标，用户选中后 TUI 暂时退出（`suspend`）把终端交给对应的安装脚本。新设计曾考虑把它并成总控的第一页「接入」。

接入过程有两个特点让 TUI 成为负担：它会持续输出大量进度、可能打开浏览器等待用户登录（最多 5 分钟）、并且需要交互式提问（例如是否把 `~/.local/bin` 写入 PATH）。这些动作都会和占用着终端的 TUI 抢标准输入输出，塞进面板里反而看不清状态。

因此决定：接入的引导是完全的纯文本逐条提问，装完自动进入总控；`assets/wizard.js` 删除，提问逻辑移进 `install.sh` / `install.ps1`。总控不再有「接入」页。

## Consequences

- 总控的职责单一：只读状态、触发运维动作，不安装任何东西。
- 探测逻辑（凭据文件与反代服务是否存在）留在 JS 里，作为运维命令的一个子命令；安装器调用它来决定装什么，总控直接复用它来渲染状态。一份实现，两个消费者。
- 「一个入口覆盖全生命周期」体现为：什么都没装时 `qodbuddy2pi` 提示去跑安装器；接入完成后同一个命令进总控。
